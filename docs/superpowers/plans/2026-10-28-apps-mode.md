# Apps Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An "Apps" engine that fuzzy-finds installed programs and starts them, on Windows, macOS and Linux.

**Architecture:** `flick-core` owns the app list type, the pure scanning/filtering rules and `AppsMode`; `flick-app`'s platform layer lists apps (Windows shell `AppsFolder` via COM; macOS/Linux call the core scans), starts them, and draws their icons. The list is rebuilt on a background thread together with the file index.

**Tech Stack:** Rust 2024, nucleo-matcher, windows 0.62 (COM, Shell), eframe/egui 0.37.

**Spec:** `docs/superpowers/specs/2026-10-28-apps-mode-design.md`

## Global Constraints

- Engine id `apps`, name `Apps`, group `OnThisPc`, placed right after `files` in `CATALOG`.
- Default engines: `["google", "youtube", "files", "apps", "wikipedia"]`.
- Waiting row title: `Finding apps...`; result label: `App`; no subtitle.
- Windows filter: drop names containing "uninstall" (any case); drop parsing names that are file paths (contain `:\`) unless the extension is `exe`, `msc` or `appref-ms`; first of a case-insensitive duplicate name wins.
- Launch: Windows `shell:AppsFolder\<parsing name>` through the shell; macOS `open <bundle>`; Linux `gio launch <desktop file>`.
- clippy `-D warnings`, `cargo fmt`, TDD.

## Review Focus

- An app list that is still `None` (first scan running): Apps shows one "Finding apps..." row with `Action::None`, Enter does nothing. Test in Task 2.
- A `.desktop` file with `[Desktop Action ...]` groups after the entry: their `Name=`/`Exec=` must not override the main entry. Test in Task 1.
- Non-UTF-8 or unreadable `.desktop` files: skipped, the scan continues. Test in Task 1.
- Two apps with the same name differing only in case (Windows): one row. Test in Task 1.
- A settings file listing `apps` from before this version does not exist, but one listing an unknown id still cleans up; `apps` must be a known id. Test in Task 2.

### Task 1: App list and scanning rules (`flick-core/src/apps.rs`)

**Files:** Create `crates/flick-core/src/apps.rs`; modify `crates/flick-core/src/lib.rs`, `crates/flick-core/src/mode.rs`.

**Interfaces — Produces:**
- `mode::Action::Launch(String)`, `mode::ResultKind::App`.
- `pub struct AppEntry { pub name: String, pub launch: String }` (derive Debug, Clone, PartialEq, Eq).
- `pub type SharedApps = Arc<RwLock<Option<Vec<AppEntry>>>>`.
- `pub fn windows_apps(items: impl IntoIterator<Item = (String, String)>) -> Vec<AppEntry>` — (display name, parsing name) → filtered list, `launch` = parsing name.
- `pub fn parse_desktop_entry(text: &str) -> Option<String>` — the app name if the file counts.
- `pub fn desktop_apps(dirs: &[PathBuf]) -> Vec<AppEntry>` — `launch` = the .desktop path; earlier dirs hide same-named files in later ones.
- `pub fn app_bundles(dirs: &[PathBuf]) -> Vec<AppEntry>` — `*.app` children of each dir, `launch` = bundle path.
- `pub fn linux_app_dirs(home: &Path, xdg_data_dirs: Option<&str>) -> Vec<PathBuf>`, `pub fn mac_app_dirs(home: &Path) -> Vec<PathBuf>` — folder lists from the spec.

### Task 3: Platform listing, launching and icons (`flick-app`)

**Files:** Create `crates/flick-app/src/platform/win/apps.rs`, `crates/flick-app/src/platform/unix/apps.rs`; modify `platform/{mod.rs,win/mod.rs,unix/mod.rs}`, `platform/win/shell_icons.rs`, `platform/unix/icons.rs`, `actions.rs`, `icons.rs`, `ui.rs`, `main.rs`, `Cargo.toml` (windows features if needed).

**Interfaces — Produces:** `platform::apps::scan() -> Vec<AppEntry>`; `platform::apps::launch(target: &str) -> std::io::Result<()>`; `IconCache::get_app(&mut self, ctx, launch: &str) -> Option<&TextureHandle>`; `Icon::App`.

- [ ] Windows scan: `SHGetKnownFolderItem(FOLDERID_AppsFolder)` → `BindToHandler(BHID_EnumItems)` → `IEnumShellItems`; names via `SIGDN_NORMALDISPLAY` and `SIGDN_PARSINGNAME`; COM initialised on the scanning thread; result through `windows_apps`. Test (Windows only, real system): the list is not empty and contains a name with "Notepad" or "Calculator".
- [ ] Windows launch: `open::that_detached(format!("shell:AppsFolder\\{target}"))`. Unix: macOS `open <path>`, Linux `gio launch <path>` (spawned, not waited on).
- [ ] Windows icon: `SHCreateItemFromParsingName("shell:AppsFolder\\…")` → `IShellItemImageFactory::GetImage(32×32, SIIGBF_ICONONLY)`; share the bitmap→RGBA code with `icon_to_image`. Unix `get_app` returns None.
- [ ] `actions::run_action` handles `Launch`; `Icon::for_kind(App) = Icon::App` (a rounded square with four dots), `for_mode("Apps") = Icon::App`; `row_icon` draws the app icon or `Icon::App`, label "App".
- [ ] `main.rs`: `SharedApps` created next to `SharedIndex`, passed to `build_modes_with`; `Reindexer::run` also scans apps on its own thread, then sets `updated` and repaints; log the count and time.
- [ ] README: Apps in the intro list and the engine table; release notes later.
- [ ] `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, `cargo test` all green; commit.
